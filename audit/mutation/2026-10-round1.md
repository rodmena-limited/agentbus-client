## Isolation finding

Default `fork` isolation is wrong for this suite: the parent has run the suite in-process and holds built singletons and
live bulkman threads. fork vs forkserver disagreed on 190 mutants (189 in `client/resilience.py`): 172 false kills,
12 false survivals, 4 false timeouts under fork. Tip from identity-9b0d0b over AgentBus; verified independently here.

Ground-truth overrides of the forkserver run: `_reply_guard.x__refuse_self_reply__mutmut_11` timeout → killed (plain
pytest: 1 failed, no hang; host load). `resilience.x__daemon_executor__mutmut_21` stays timeout (plain pytest hangs to
the 600 s limit).

## Largest test gaps (high severity)

- `_signing.sign / verify / canonical_bytes / fingerprint`: no in-process test runs them with a real key. A `verify` that rejects every signature leaves 2967/2967 tests green (spot-checked). Signing failures are swallowed by `base._sign_if_possible`, so a broken `sign` silently ships unsigned mail.
- `client/sync_verify.py`: 338/338 mutants no tests; the verify CLI tests fake `_bus`.
- `onboarding/_credentials.py`: `doctor_credential_scope`, `_scope_of_bearer`, `_inherited_flag` untested (209 no tests).
- `client/resilience.py`: 30 surviving mutants violate the durable spec `resilience_breaker_classifier` (`_cb_window`, `_root_cause`, `_breaker_should_handle`, `_sdk_safety_net`); `AGENTBUS_SDK_*` env overrides untested.
- `hooks/_gate.py`: real `_bus_reachable` untested; request URL, method and headers never asserted; boundary at exactly `GUARD_FIELD_LIMIT` untested.
- `identity.py`: fingerprints and session keys only compared for equality, never against known values.
- `sealing.py`: secret file and directory modes untested; `_armor` 64-column wrap untested (70/65 breaks real `age`).
